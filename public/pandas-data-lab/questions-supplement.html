왜 FF는 255일까?

8비트는 왜 256가지를 표현할까요?

여러분은 컴퓨터가 모든 데이터를 0과 1로 처리한다는 말을 들어 보았을 겁니다. 컴퓨터 내부의 전자회로는 전압이 높고 낮은 두 상태처럼 서로 구별되는 상태를 이용합니다. 우리는 이 상태를 0과 1로 표현하고, 하나의 0 또는 1을 비트(bit)라고 부릅니다.

비트가 하나라면 0과 1, 두 가지 경우가 가능합니다. 두 개라면 00, 01, 10, 11로 네 가지가 되지요. 비트를 하나 더 추가할 때마다 표현 가능한 상태의 개수가 두 배로 늘어납니다.

그래서 비트가 8개일 때는 2⁸ = 256가지 상태를 나타냅니다. 보통 8비트 = 1바이트라고 부릅니다. 여기서 256은 상태의 개수이지 최댓값이 아닙니다.

0부터 세기 때문에 가장 큰 수는 255가 됩니다. 0, 1, 2 … 255까지 세면 정확히 256개의 숫자가 있기 때문입니다.

8비트(bit) = 0 또는 1인 자리 8개
11111111

각 비트에 두 가지 선택지가 있으므로 2×2×2×2×2×2×2×2가지입니다.

2⁸ = 256가지 (0~255)

이 값은 부호 없는 8비트 정수의 범위입니다. 음수도 나타내는 부호 있는 8비트 정수는 일반적으로 −128~127을 나타냅니다.

학생 질문: “256가지라고 했는데 왜 최댓값이 256이 아니라 255인가요?”

답: 출발점인 0도 하나의 상태입니다. 예를 들어 0부터 9까지는 열 개의 숫자가 있지만 최댓값은 9입니다. 마찬가지로 0부터 255까지는 256개의 숫자이며, 8비트로 나타내는 값의 범위도 그렇게 정해집니다.

8비트는 256가지 상태를 표현하고, 부호 없는 값의 범위는 0부터 255까지입니다.

16진수 FF는 왜 255일까요?

우리가 평소 사용하는 10진수는 0부터 9까지 열 개의 기호로 수를 표현합니다. 9 다음에는 자리를 올려 10이라고 쓰지요. 16진수는 한 자리에서 0부터 15까지 표현해야 하므로, 0~9 뒤에 A, B, C, D, E, F라는 여섯 글자를 추가합니다.

이때 A는 10, B는 11, …, F는 15입니다. 16진수의 F는 알파벳 단어가 아니라 숫자 15를 나타내는 기호입니다.

10진수 25를 2×10 + 5로 계산하듯이, 16진수 FF는 왼쪽 자리의 15에 16을 곱하고 오른쪽 자리의 15를 더합니다. 15×16+15=255가 됩니다.

16진수 한 자리는 0~F까지 16가지 경우를 나타냅니다. 16은 2⁴이므로 한 자리가 4비트에 대응합니다. 따라서 두 자리는 8비트에 대응하는 것이죠.

FF₁₆ = 15 × 16 + 15 = 255₁₀

16진수 두 자리(FF) = 4비트 + 4비트 = 8비트

16진수 F는 15를 뜻하므로 FF는 10진수 255입니다.

Python 코드에서는 왜 0xFF라고 쓸까요?

여러분이 Python 코드를 작성할 때 apple, score처럼 영어로 변수 이름을 만들 수 있다는 것을 기억하나요? 그런데 FF라고만 적으면 Python은 이것을 16진수 숫자가 아니라 FF라는 이름의 변수라고 판단하려고 합니다.

숫자 255를 16진수로 표현하고 싶다면, Python에 “지금부터 나오는 글자는 16진수 숫자입니다”라고 알려줘야 합니다. 그때 앞에 붙이는 표시가 0x입니다. 그래서 0xFF는 변수 이름이 아니라 정수 255로 인식됩니다.

그럼 맨 앞의 0은 무엇일까요? 프로그램에서 변수는 문자로 시작할 수 있지만 숫자로 시작할 수 없습니다. 숫자 0을 먼저 적고, 그 뒤에 16진수(hexadecimal)를 뜻하는 x를 붙이는 표기법이 프로그래밍 언어에 정착한 것입니다. Python에서는 0x라는 접두사가 하나의 규칙입니다. x를 변수처럼 따로 읽는 것이 아닙니다.

print(0b11111111)  # 2진수 정수
print(255)         # 10진수 정수
print(0xFF)        # 16진수 정수
print(0o377)       # 8진수 정수

print(hex(255))     # '0xff' 문자열
print(int("FF", 16)) # 255

이 코드를 실행하면 앞의 네 줄은 모두 255를 출력합니다. 숫자를 저장할 때 진법에 따라 자료의 종류가 달라지는 것이 아니라, 같은 숫자를 어떻게 적느냐만 다릅니다. 다만 hex(255)의 결과는 '0xff'라는 문자열이므로 정수 자체와는 구별해야 합니다.

비교: 0xFF는 숫자 255이고, "#FF0000"은 화면에 그릴 색상을 지정하는 문자열입니다. 두 문법을 섞어 쓰면 안 됩니다.
0x는 “16진수 정수”라는 접두사이며, 0xFF는 숫자 255입니다.

웹 색상에는 왜 #FF0000을 쓸까요?

컴퓨터 모니터는 빨강(Red), 초록(Green), 파랑(Blue)의 빛을 섞어 다양한 색을 만듭니다. 이를 RGB라고 부릅니다. 색의 세기를 0~255 값으로 표현하는 경우, 각 채널에 8비트가 필요합니다.

예를 들어 빨강의 세기를 255, 초록과 파랑의 세기를 0으로 설정하면 빨강이 나타납니다. 이를 16진수로 바꾸면 R=FF, G=00, B=00이 되고, 세 값을 순서대로 이어 붙인 것이 FF0000입니다.

여기에 웹 CSS에서 사용하는 색상 표기 기호 #를 앞에 붙여 #FF0000이라고 적습니다. 이것은 “뒤에 여섯 자리는 RGB 색상 코드입니다”라는 뜻입니다. Python의 0xFF는 하나의 정수이고, 웹의 #FF0000은 색을 나타내는 별도의 표기입니다.

색상Hex 코드R, G, B의 10진수 값
빨강#FF0000255, 0, 0
초록#00FF000, 255, 0
파랑#0000FF0, 0, 255
노랑#FFFF00255, 255, 0
하양#FFFFFF255, 255, 255
검정#0000000, 0, 0

그럼 #FF라고만 써도 될까요?

우리가 지금 배우는 기본 RGB 형식은 #RRGGBB, 여섯 자리입니다. #FF라고만 적으면 RGB 각 채널을 모두 지정한 것이 아니므로 CSS 색상 코드로 올바르지 않습니다. 웹 CSS에서는 #F00처럼 세 자리로 줄여 쓰는 특별한 규칙도 있습니다. 이때 #F00은 #FF0000과 같은 빨강입니다.

여덟 자리 색상 코드는 무엇인가요?

CSS에서는 RGB 여섯 자리 뒤에 투명도(Alpha)를 나타내는 두 자리를 더해 #RRGGBBAA로 표현할 수 있습니다. #FF000080이라면 빨강의 알파 채널이 16진수 80, 즉 128/255이므로 약 50%의 불투명도를 가진 빨강입니다.

단, Python Turtle에서는 기본적으로 #RRGGBB 여섯 자리를 사용하세요. CSS의 여덟 자리 색상 코드를 그대로 쓰면 오류가 날 수 있습니다.

import turtle

turtle.pencolor("#FF5733")  # Hex 색상
turtle.forward(100)

turtle.pencolor("cyan")     # 영문 색상 이름
turtle.forward(100)
turtle.done()
#RRGGBB에서 두 자리씩 빨강·초록·파랑의 세기를 표현합니다.

Arduino의 255와 FF는 어떤 관계일까요?

우리가 Arduino Uno를 실습할 때 LED 밝기를 바꾸는 코드로 analogWrite(LED, 255)를 사용했습니다. PWM 출력에서 0은 0% 듀티, 255는 약 100% 듀티에 해당합니다. 여기서 255도 부호 없는 8비트 범위의 최댓값입니다.

255를 16진수로 적으면 FF이므로 analogWrite(LED, 0xFF)도 같은 숫자 255를 전달합니다. 단지 숫자를 적는 방식만 바뀐 것이죠. 웹의 빨강 채널이 FF라고 표현될 때도 그 채널의 숫자값은 255입니다.

analogWrite(LED, 0);     // PWM 듀티 0%
analogWrite(LED, 128);   // PWM 듀티 약 50%
analogWrite(LED, 255);   // PWM 듀티 약 100%
analogWrite(LED, 0xFF);  // 위의 255와 같은 숫자

다만 PWM은 LED에 걸리는 전압을 연속적으로 조정하는 방식이 아닙니다. 매우 빠르게 켜고 끄는 시간의 비율을 조절합니다. 사람 눈에 보이는 밝기는 그 비율과 정확하게 일치하지 않을 수 있습니다. 이것이 프로그래밍에서 숫자를 이해하면서도 실제 하드웨어의 특성을 함께 알아야 하는 이유입니다.

Arduino의 255와 웹 RGB 채널의 FF는 숫자 255라는 점에서 연결되지만, 사용 목적은 다릅니다.
