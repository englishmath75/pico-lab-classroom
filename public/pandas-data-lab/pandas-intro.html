01. 엑셀이 있는데 왜 판다스를 배울까요?

친구들의 일주일 독서 시간을 정리한다고 생각해 보세요. 엑셀은 셀을 클릭하여 입력하고 바로 표를 확인하기 좋습니다. 판다스는 같은 정리·계산 과정을 코드로 기록하고, 다음 주 자료에도 다시 적용하기 좋습니다. 둘은 목적에 따라 함께 사용할 수 있습니다.

비교Excelpandas
기본 모습행·열로 된 워크시트, 셀에 값·수식 입력Series·DataFrame 객체를 코드로 다룸
전체 값에 5 더하기B2에 =A2+5를 넣고 아래로 채우기s + 5
일부분 선택셀 범위 A2:A4 선택s.iloc[0:3] 또는 이름표로 .loc
조건에 맞는 자료필터 기능s[s >= 30]
같은 분석 반복수식·Power Query·매크로 등으로 자동화 가능코드를 다시 실행하여 같은 절차 재현
대용량 처리워크시트 한 장에는 행·열 한도가 있음고정된 워크시트 행 한도 대신 메모리·연산 비용의 제약
속도수식 수·재계산·서식·하드웨어에 영향받음자료형·연산 방식·메모리 사용량에 영향받음

행과 열, 그리고 2의 거듭제곱

행(row)은 가로 한 줄이며 위에서 아래로 쌓입니다. 열(column)은 세로 한 줄이며 왼쪽에서 오른쪽으로 늘어납니다.

워크시트행 수 · 세로로 쌓인 가로줄열 수 · 가로로 나열된 세로줄
Excel 2003 이전 .xls65,536 = 2¹⁶256 = 2⁸
Excel 2007 이후 .xlsx1,048,576 = 2²⁰16,384 = 2¹⁴

2¹⁰ = 1,024, 2¹⁵ = 32,768, 2¹⁶ = 65,536입니다. 최신 엑셀의 워크시트 한도를 말하는 것이며, Power Query·데이터 모델까지 모두 이 행 수로 제한된다는 뜻은 아닙니다. “100만 행을 넘으면 어떤 파일도 열 수 없다”, “1만 행이면 반드시 느리다”는 설명은 피하세요.

선생님 설명 · 소리 내어 읽기

오늘 목표는 엑셀을 없애는 것이 아닙니다. 여러분이 알고 있는 표를 파이썬으로 다루는 방법을 하나 더 배우는 것입니다. 데이터를 넣고, 필요한 것만 꺼내고, 계산하고, 그 과정을 다시 실행해 봅시다.

02. NumPy와 pandas는 왜 탄생했을까요?

2005 · NumPy

Travis Oliphant가 이전 수치 계산 도구들의 흐름을 통합하며 NumPy를 개발했습니다. 숫자를 배열로 다루고 과학·수학 계산을 효율적으로 수행하기 위한 기반입니다.

2008 · pandas

Wes McKinney가 AQR에서 데이터 분석 도구를 개발하기 시작했습니다. 이름표가 있는 표, 날짜, 빠진 값, 서로 다른 자료의 결합처럼 실제 분석의 불편을 해결하는 방향으로 발전했습니다.

1학기에 배운 NumPy의 ndarray는 배열 계산의 기반입니다. pandas의 Series는 값에 인덱스 이름표를 붙이고, DataFrame은 행·열이 있는 표를 제공합니다. pandas는 NumPy를 중요한 기반으로 활용하지만, 모든 열이 항상 하나의 NumPy 배열이라는 뜻은 아닙니다. 자료형에 따라 다른 배열 구현도 사용할 수 있습니다.

벡터 연산: 코드 한 줄이 CPU 명령 한 번은 아닙니다

s + 5는 “이 Series의 각 값에 5를 더하라”는 뜻입니다. 내부적으로도 값을 읽고 계산하고 결과를 저장합니다. 파이썬에서 값마다 반복문을 해석하는 부담을 줄이고, 자료형에 맞는 최적화된 내부 연산을 이용할 수 있어서 효율적입니다.

기본적인 숫자 배열은 같은 크기의 값들을 규칙적인 메모리 배치로 다룰 수 있습니다. 예를 들어 64비트 정수 10,000개는 값 데이터만 약 80,000바이트가 필요합니다. 10,000개가 메모리의 한 칸에 들어가는 것이 아니라 여러 저장 공간을 차지합니다. CPU가 일부 값을 묶어서 처리할 수 있어도, 배열 전체를 무조건 한 명령으로 계산하는 것은 아닙니다.

오버헤드는 실제 덧셈 외에 타입 확인, 반복 제어, 객체 접근 등 준비·관리 과정에 드는 비용입니다. pandas가 이 비용을 모두 없애거나, 언제나 Excel보다 빠른 것은 아닙니다.

03. 설치, import, 별명 pd

위 명령은 Python 코드 창에 넣지 않습니다. 설치 후 Python 파일에서는 import pandas as pd를 사용합니다. as pd는 짧은 별명을 붙이는 문법입니다. pd는 관례이며 특별한 예약어는 아닙니다.

07. 슬라이싱: 시작·끝·간격

슬라이싱은 시작:끝:간격으로 연속된 구간을 선택하는 문법입니다. iloc는 끝 위치 제외, loc는 끝 이름표 포함이 핵심입니다. 아래 loc 예제는 이름표가 중복되지 않고 시작·끝 이름표가 실제로 있는 경우입니다. 요일의 사전순이 아니라 현재 나열된 순서를 따릅니다.

코드선택되는 요일이유
s.iloc[1:4]화·수·목위치 1, 2, 3 · 4는 제외
s.loc["화":"목"]화·수·목끝 이름표 목도 포함
s.iloc[:3]월·화·수처음부터 위치 3 직전까지
s.iloc[2:]수·목·금위치 2부터 끝까지
s.iloc[-3:]수·목·금뒤에서 세 항목
s.iloc[::2]월·수·금두 칸씩
s.iloc[::-1]금·목·수·화·월역순
s.iloc[4:0:-2]금·수위치 4, 2 · 0 제외

질문이 나왔을 때

괄호와 대괄호는 왜 다른가요?
pd.Series(...)는 객체 생성 호출, s.iloc[...]는 위치 선택입니다. s.sum()은 메서드 호출입니다.
요일 인덱스는 자동으로 월~금 순서가 되나요?
아닙니다. 처음 지정한 순서와 이후 정렬·연산에 따라 달라집니다. 결과의 인덱스를 확인하세요.
슬라이스를 수정하면 원본도 바뀌나요?
버전과 복사 정책에 따라 혼동될 수 있습니다. 독립 작업은 part = s.iloc[:3].copy(), 원본 수정은 s.loc[...] = 값으로 명시하세요.
예전 영상에서 s[0]과 append가 보이는데요?
위치 선택은 s.iloc[0], 연결은 pd.concat으로 연습하세요. 제거되거나 의미가 바뀐 옛 문법을 답안으로 외우지 않습니다.
